## 0. 一页纸摘要

**一句话定位**：让企业知识「找得到、答得准、可追溯、管得住」。

**目标用户**：知识管理员、业务提问者、内容贡献者、平台管理员、开发者。

**核心闭环**：

```
接入 → 解析 → 组织/治理 → 检索 → 带引用回答 → 反馈 → 知识缺口 → 补充内容
```

**与普通文档库/聊天机器人的差异**：

1. **引用可追溯**：答案精确到段落/页码，可点击回原文。
2. **权限原生**：ACL 进入召回条件，先过滤再检索，而不是答完再裁剪。
3. **可运营**：知识缺口、未命中问题、评测集形成持续改进闭环。
4. **可开放**：REST API、Webhook、嵌入式组件、MCP Server。

**MVP 范围**：知识库管理、文档上传与解析、混合检索、带引用问答、基础 ACL、反馈、管理后台。

**北极星指标**：周活跃提问者中，获得「有帮助」回答的用户占比（Helpful Answer Rate）。

## 1. 背景与问题

### 1.1 现状

企业知识分散在网盘、IM、邮件、Wiki、工单和员工大脑中：

- **找不到**：关键词搜索无法理解自然语言，找不到跨文档的答案。
- **答不准**：通用大模型不了解企业私有知识，容易一本正经地编造。
- **不敢用**：答案没有出处，无法验证；敏感文档可能被无权用户看到。
- **管不住**：文档过期、重复、无 owner，知识库半年后变成「文件坟场」。
- **无法迭代**：不知道用户问了什么、哪些问题答不上来、改动后效果变好还是变坏。

### 1.2 机会

以「可信回答」为核心，而不是以「文档存储」为核心，把知识接入、治理、检索、消费、反馈串成闭环。企业愿意为**减少重复问答、缩短新人上手时间、降低错误决策风险**付费。

### 1.3 不做的事（v1 非目标）

- 不做通用在线文档编辑器（只做知识内容的最小编辑能力）。
- 不自研基础大模型、向量数据库、OCR 引擎。
- 不做开放的公网问答社区。
- 不做复杂知识图谱推理与自动化 Agent 编排（P2 再评估）。

## 2. 产品目标与成功指标

### 2.1 产品目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G1 | 找得到 | 自然语言提问，30 秒内返回结果 |
| G2 | 答得准 | 基于企业知识回答，不编造；无依据时明确拒答 |
| G3 | 可追溯 | 每条事实性回答都有可点击引用 |
| G4 | 管得住 | 权限、审计、版本、有效期可管理 |
| G5 | 能变好 | 反馈、缺口、评测驱动持续优化 |

### 2.2 成功指标

| 指标 | 定义 | MVP 目标 |
| --- | --- | --- |
| Helpful Answer Rate | 点赞数 /（点赞 + 点踩） | ≥ 75% |
| 引用点击率 | 有点击引用的回答 / 有引用的回答 | ≥ 25% |
| 无答案率 | 明确拒答的消息 / 总提问消息 | ≤ 15%（且拒答正确率 ≥ 90%） |
| 首 Token 时延 | 请求到首个流式片段的 P95 | ≤ 2s |
| 检索时延 | 召回 + 重排完成 P95 | ≤ 800ms |
| 入库成功率 | 成功进入 ready 的文档 / 提交文档 | ≥ 98% |
| 7 日留存 | 首次提问后 7 日内再次提问的用户占比 | ≥ 35% |
| 单次回答成本 | LLM + Embedding + 重排的均值 | 有预算告警，MVP 不设硬指标 |

## 3. 用户与核心场景

### 3.1 用户角色

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 知识管理员（KM） | 负责建库、接数据、治理内容 | 快速接入、看清质量、定位缺口 |
| 业务提问者 | 销售、客服、研发、HR、新人 | 快速得到可信答案 |
| 内容贡献者 | 领域专家、文档 Owner | 低摩擦贡献、反馈能落到自己 |
| 平台管理员 | IT/安全/运营 | 权限、审计、配额、成本可控 |
| 开发者 | 内部系统/合作方 | API、Webhook、MCP 集成 |

### 3.2 核心场景

| 编号 | 场景 | 用户 | 成功标准 |
| --- | --- | --- | --- |
| S1 | 新员工问「差旅报销标准是多少」 | 新人 | 10 秒内得到答案 + 制度原文引用 |
| S2 | 客服查「退款政策与例外」 | 客服 | 答案包含适用条件与例外，引用可点 |
| S3 | 销售查「某产品报价边界」 | 销售 | 不越权看到机密报价文档 |
| S4 | 研发查「SSO 配置步骤」 | 研发 | 返回步骤 + 对应文档段落 |
| S5 | KM 发现「最近 30 天有 40 次没答案」 | KM | 一键看到缺口聚类并指派补充 |
| S6 | 开发者把问答嵌入内部工单系统 | 开发者 | 通过 API/MCP 调用，带权限与引用 |

### 3.3 核心用户旅程

```mermaid
flowchart LR
  A[创建工作区/知识库] --> B[上传或连接内容]
  B --> C[解析/分块/向量化]
  C --> D[配置权限与检索策略]
  D --> E[成员提问]
  E --> F[混合检索 + 重排]
  F --> G[流式回答 + 引用]
  G --> H[点赞/点踩/纠错]
  H --> I[知识缺口与评测]
  I --> J[补充/修订文档]
  J --> C
```

## 5. 功能需求

### 5.1 工作区与知识库

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-KB-01 | P0 | 创建、编辑、归档知识库 | 名称在工作区内唯一；归档后不可被检索 |
| FR-KB-02 | P0 | 知识库可见性：私有 / 团队 / 组织 | 可见性变化 5s 内对检索生效 |
| FR-KB-03 | P0 | 知识库配置：Embedding 模型、分块策略、TopK、阈值、重排开关、上下文预算 | 配置变更生成新版本，旧会话不受影响 |
| FR-KB-04 | P0 | 知识库概览：文档数、就绪率、提问数、无答案率 | 数据延迟 ≤ 5 分钟 |
| FR-KB-05 | P1 | 知识库模板：制度库、产品库、客服库 | 模板预置元数据字段与提示词 |
| FR-KB-06 | P1 | 知识库复制/导出 | 导出不含密钥与审计数据 |

**规则**

- 知识库属于唯一工作区，禁止跨工作区引用文档。
- 归档为软删除：文档与引用快照保留，检索立即排除。
- 删除知识库需二次确认，并在 30 天回收站后可彻底删除。

### 5.2 内容接入

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-ING-01 | P0 | 文件上传：PDF、DOCX、PPTX、XLSX、Markdown、TXT、HTML | 单文件 ≤ 100MB；批量 ≤ 50 个 |
| FR-ING-02 | P0 | 解析状态与失败原因可见 | 展示阶段、错误码、可重试 |
| FR-ING-03 | P0 | 内容去重 | 同库相同内容哈希不重复向量化 |
| FR-ING-04 | P0 | 手动录入 / Markdown 新建 | 支持标题、正文、元数据 |
| FR-ING-05 | P0 | 重新索引 | 不改变文档 ID；生成新版本 |
| FR-ING-06 | P1 | URL 抓取与网页正文提取 | 支持单页与站点地图（可选） |
| FR-ING-07 | P1 | SaaS 连接器：飞书、钉钉、Notion、Confluence | 支持手动/定时同步，展示同步统计 |
| FR-ING-08 | P1 | OCR 与表格结构还原 | 扫描 PDF 可检索；表格按行/列保留语义 |
| FR-ING-09 | P1 | 音视频转写 | 生成带时间戳的转写文本 |
| FR-ING-10 | P1 | 批量导入/导出 | CSV/JSON 元数据映射；失败行可下载 |
| FR-ING-11 | P2 | Git 仓库、S3、数据库连接器 | 增量同步、分支/路径过滤 |

**入库流水线**

```
发现 → 下载 → 解析 → 规范化 → 分块 → 向量化 → 索引 → 激活版本
```

**规则**

- 每个阶段幂等，失败重试不产生重复分块。
- 解析失败保留原始文件与错误现场，支持「仅重跑解析」。
- 文档内容哈希未变化时跳过重新向量化。
- 单个文档失败不影响同批次其他文档。

### 5.3 知识组织与治理

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-GOV-01 | P0 | 目录树：新建、重命名、移动、排序 | 移动不改变文档 ID 与引用 |
| FR-GOV-02 | P0 | 元数据 Schema：文本、枚举、日期、人员、多选 | 发布时校验；支持按元数据过滤检索 |
| FR-GOV-03 | P0 | 文档生命周期：草稿、已发布、已归档、有效期 | 仅「已发布且在有效期」可被检索 |
| FR-GOV-04 | P0 | 文档 Owner 与到期提醒 | 到期前 14/7/1 天通知 Owner |
| FR-GOV-05 | P0 | 文档版本与回滚 | 历史版本可查看；回滚生成新版本 |
| FR-GOV-06 | P0 | 资源级 ACL：知识库/目录/文档 | 未授权内容不出现在召回结果与引用中 |
| FR-GOV-07 | P0 | 审计日志：登录、权限、上传、删除、导出、问答 | 只追加、不可篡改；保留 ≥ 1 年 |
| FR-GOV-08 | P1 | 标签、同义词、术语表 | 同义词参与查询扩展 |
| FR-GOV-09 | P1 | 敏感级别与脱敏 | `public/internal/confidential/restricted` 四级 |
| FR-GOV-10 | P1 | 内容质量检查：空文档、乱码、超短、重复 | 入库后给出质量分与问题提示 |
| FR-GOV-11 | P2 | 知识图谱：实体、关系、关联推荐 | 不阻塞主检索链路 |

**治理规则**

- 文档必须有 Owner；无 Owner 的文档在 30 天后标记为「待认领」。
- 有效期过期自动转 `expired`，检索排除，但保留引用快照。
- 敏感级别高于用户 clearance 的文档，即使有 ACL 也不返回。

| FR-RET-06 | P0 | 父子块与上下文扩展 | 命中子块时返回父块上下文 |
| FR-RET-07 | P0 | 检索调试台 | 展示查询改写、候选、分数、耗时 |
| FR-RET-08 | P1 | 意图路由：FAQ / 文档 / 结构化数据 / 闲聊 | 结构化问题可走 Text2SQL |

| 参数 | 默认值 |
| --- | --- |
| 向量召回 | Top 50 |
| 关键词召回 | Top 50 |
| 融合 | RRF，k=60 |
| 重排候选 | Top 30 |

### 5.5 问答与引用

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-CHAT-01 | P0 | 多轮会话：新建、重命名、删除、历史列表 | 会话绑定可选知识库范围 |
| FR-CHAT-02 | P0 | 流式输出、停止生成、重新生成 | SSE 事件顺序正确，可中断 |
| FR-CHAT-03 | P0 | 引用：文档标题、段落、页码、原文链接 | 点击可定位到原文锚点 |
| FR-CHAT-04 | P0 | 拒答与澄清 | 无依据时明确说明，不编造 |
| FR-CHAT-05 | P0 | 多知识库选择 | 可跨库提问，权限取交集 |
| FR-CHAT-06 | P0 | 回答格式：步骤、表格、代码块、清单 | Markdown 渲染正确 |
| FR-CHAT-07 | P1 | 分享会话 | 支持只读链接、有效期、水印 |
| FR-CHAT-08 | P1 | 模型选择与成本提示 | 管理员可限制可选模型 |
| FR-CHAT-09 | P1 | 回答溯源校验 | 引用必须来自本次召回结果 |
| FR-CHAT-10 | P2 | 语音提问与朗读 | 移动端优先 |

**回答契约**

1. 先给结论，再给依据和步骤。
2. 每个事实性结论至少一个引用；引用编号与文末来源一致。
3. 检索结果不足时输出「根据现有知识无法确认」，并给出下一步建议。
4. 不输出无权访问的内容，不猜测文档中不存在的信息。
5. 引用必须来自本次检索候选，禁止模型自行编造链接。

### 5.6 反馈与知识缺口

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-FB-01 | P0 | 点赞/点踩 + 原因 | 原因枚举：不准确、不完整、过时、引用错误、不相关、其他 |
| FR-FB-02 | P0 | 纠错与补充答案 | 可提交修正文本，通知文档 Owner |
| FR-FB-03 | P0 | 反馈状态流转：待处理、已处理、忽略 | 处理结果可回访 |
| FR-FB-04 | P1 | 未命中问题聚类 | 按语义聚类，生成缺口主题 |
| FR-FB-05 | P1 | 知识缺口看板 | 出现次数、影响用户、关联知识库、负责人 |
| FR-FB-06 | P1 | 缺口转任务 | 一键创建待办/工单（可先站内） |

**缺口生成规则**

- 触发条件：无检索结果、最高分低于阈值、用户点踩、用户追问「没回答」。
- 同一语义簇 7 天内 ≥ 3 次才进入看板，避免噪声。
- 缺口关闭条件：关联文档发布并被至少一次成功回答验证。

## 6. 权限模型

### 6.1 角色

| 角色 | 工作区管理 | 成员管理 | 知识库管理 | 文档编辑 | 文档发布 | 提问 | 审计 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Owner | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Admin | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Editor | — | — | ✓ | ✓ | ✓ | ✓ | — |
| Contributor | — | — | — | ✓ | — | ✓ | — |
| Reader | — | — | — | — | — | ✓ | — |

### 6.2 资源权限

- 资源类型：知识库、目录、文档。
- 权限：`read`、`write`、`manage`。
- 授权主体：用户、用户组、工作区角色。
- 继承：知识库 → 目录 → 文档；子级可追加授权，不可越权收窄上级已授权的读取（v1 不做 deny）。
- 管理员对工作区内全部资源有 `manage`。
- **检索必须携带权限过滤条件**，禁止「先检索后裁剪」。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 检索 P95 ≤ 800ms；首 Token P95 ≤ 2s；文档列表 P95 ≤ 300ms |
| 规模 | 单知识库 10 万文档 / 100 万分块；单工作区 100 并发问答 |
| 可用性 | 核心问答 99.9%；入库允许异步与重试 |
| 安全 | 租户隔离、传输/存储加密、密钥托管、Prompt 注入防护、PII 脱敏 |
| 合规 | 数据导出、删除权、保留策略、审计 ≥ 1 年、数据驻留（企业版） |
| 可观测 | 全链路 TraceID；检索轨迹、Token 用量、成本可查 |
| 成本 | Embedding 缓存、增量索引、按工作区预算告警 |
| 可访问性 | 键盘操作、对比度、屏幕阅读器基础支持 |

## 9. 发布计划

### MVP（建议 6–8 周）

**范围**：FR-KB-01~04、FR-ING-01~05、FR-GOV-01~07、FR-RET-01~07、FR-CHAT-01~06、FR-FB-01~03、FR-ADM-01~02。

**退出标准**：

- 100 篇真实文档入库成功率 ≥ 98%。
- 50 条黄金问答集上，引用覆盖率 100%，有用率 ≥ 70%。
- 权限测试：无授权用户无法通过任何入口看到文档内容或引用。
- 首 Token P95 ≤ 3s，检索 P95 ≤ 1s（MVP 放宽）。

### P1（MVP 后 8–12 周）

连接器、OCR、评测体系、知识缺口、API/Webhook、嵌入组件、SSO。

### P2（按客户需求）

MCP、IM 机器人、知识图谱、Agent 工作流、私有化、多语言增强。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| PDF/扫描件解析质量差 | 答不准、信任崩塌 | 解析质量评分、OCR 兜底、失败可见、人工修正 |
| 权限漏洞 | 数据泄露，事故级 | 检索前过滤、权限变更扇出、越权回归测试、审计 |
| 模型幻觉 | 错误决策 | 强制引用、拒答阈值、忠实度评测、抽检 |
| 冷启动内容不足 | 首次体验差 | 模板库、示例问答、导入向导、缺口提示 |
| 成本失控 | 毛利下降 | Embedding 缓存、增量索引、上下文预算、模型分级 |
| 连接器维护成本 | 交付拖慢 | 优先标准协议（S3/WebDAV/API），SaaS 连接器按客户排期 |
| 知识库腐化 | 长期价值下降 | Owner 制、有效期、到期提醒、质量分、缺口闭环 |

## 11. 开放问题

1. 向量存储：MVP 用 PostgreSQL + pgvector，何时切换到专用向量库？触发条件是什么？
2. 文档编辑：是否需要块级协同编辑，还是只做 Markdown/富文本最小编辑？
3. 计费：按席位、按文档量还是按问答次数？需要与配额模型一起定。
4. 私有化：首个企业客户是否要求离线模型与本地部署？
5. 多语言：首发是否必须支持中英混合检索与回答？
6. 数据驻留：是否需要按区域拆分工作区与存储？

## 12. 术语表

| 术语 | 含义 |
| --- | --- |
| 工作区 Workspace | 租户隔离单位，包含成员、知识库、配额 |
| 知识库 Knowledge Base | 一组文档与检索配置的集合 |
| 文档 Document | 知识的最小管理单元，拥有生命周期与 Owner |
| 文档版本 Document Version | 文档某次内容快照，分块与向量归属于版本 |
| 分块 Chunk | 检索的最小文本单元，可有父子关系 |
| 数据源 Data Source | 外部内容来源及其同步配置 |
| 检索轨迹 Retrieval Trace | 一次问答的查询改写、候选、分数、耗时记录 |
| 引用 Citation | 回答与原文片段的关联快照 |
| 知识缺口 Knowledge Gap | 用户问不到/答不好的问题聚类 |
| 评测集 Eval Dataset | 用于离线回归的问题与标准答案集合 |
